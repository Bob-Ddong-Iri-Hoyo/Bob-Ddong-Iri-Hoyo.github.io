## Wine Drive 이해하기

Windows 프로그램은 경로를 Windows 방식의 주소로 인식합니다.
예를 들어 `C:myapp/some.exe`와 같은 경로를 기대합니다.

반면 macOS는 `/Users/myID/some.app`처럼 Unix/Linux 스타일의 경로를 사용합니다.
따라서 Wine은 Windows 프로그램이 이해할 수 있는 드라이브 경로를 별도로 제공해야 합니다.

## C: Drive

Wine은 Windows 앱을 위해 C: Drive를 macOS의 특정 경로로 매핑합니다.
예를 들어 다음과 같은 방식으로 Wine prefix 내부 경로를 C: Drive처럼 보여 줍니다.

```text
/User/MyID/WinePrefix -> C:/
```

C: Drive는 Wine이 지정한 macOS 경로의 별칭으로 볼 수 있습니다.
다만 C: Drive만으로는 해당 prefix 내부 경로만 확인할 수 있습니다.

```text
C:/Program Files/
C:/Users/
...
```

이 구조에서는 외부에 있는 다른 macOS 폴더나 프로그램에 접근할 수 없습니다.
즉 매핑된 `C:/` 내부만 사용할 수 있습니다.

## Z: Drive

Z: Drive는 macOS의 Root인 최상위 경로 `/`를 가리키는 별칭입니다.
C: Drive가 prefix 내부를 다룬다면, Z: Drive는 macOS 시스템의 외부 경로까지 나타낼 수 있습니다.

따라서 Z: Drive는 외부 경로에 있는 Windows 앱을 실행하거나 다른 Prefix와 공용으로 사용하는 앱을 관리할 때 편리합니다.
다만 최상위 경로부터 전체 경로를 매번 지정해야 하므로, 반복해서 사용하기에는 번거로울 수 있습니다.

## G: Drive

BDIH Launcher는 여러 Bottle이 함께 사용할 수 있는 G Drive(G:) 경로를 추가로 제공합니다.
G: Drive는 사용자가 지정한 외부 경로를 짧은 Windows 드라이브 경로처럼 사용할 수 있게 해 줍니다.

이 경로를 사용하면 용량이 큰 게임 데이터를 Bottle 밖에 보관하면서도, 각 Bottle에서는 같은 G: Drive로 접근할 수 있습니다.

<Aside type="tip">
G: Drive는 설정의 Wine 항목에서 지정합니다.
게임을 저장할 위치를 선택한 뒤, 런처를 제외한 게임 데이터를 이 공간에 설치합니다.
</Aside>

<Aside type="caution">
G: Drive 경로를 변경할 때는 실행 중인 모든 Bottle을 먼저 종료해야 합니다.
이미 실행 중인 Bottle은 새로 지정한 G: Drive를 인식하지 못할 수 있습니다.
</Aside>
