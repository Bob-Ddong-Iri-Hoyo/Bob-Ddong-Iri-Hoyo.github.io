## 文書の範囲

このセクションは、バブトンイリホヨ ランチャーアプリ、Wine ランタイム、DXMT ランタイムを自分でビルドしたい保守者、またはリリース成果物の構造を理解したい保守者向けの文書です。
ランチャーをインストールしてゲームを実行するだけの場合、このセクションに沿って自分でビルドする必要はありません。

  <Card title="BDIH-Launcher">

  <Card title="wine-build">

  </Card>

  </Card>

## 読む順序

1. **ビルド文書の概要**で全体構造とルールを確認します。
2. **BDIH Launcher ビルド**でランチャーアプリのローカルビルド、パッケージング、テスト、配布ポリシーを確認します。
3. **Wine ランタイムのビルド**で WineHQ 系列と CrossOver 系列のランタイムをどう作るか確認します。
4. **DXMT ビルド**で Eternal Return 向け DXMT パッチとパッケージングの流れを確認します。
5. **リリースとメタデータ**でランチャーが読む manifest、artifact 構造、ライセンス基準を確認します。

## 基準リポジトリ

各リポジトリのビルドコマンドとパッチ適用順序が基準です。
文書とスクリプトが食い違って見える場合は、まずスクリプトを確認してください。

- Wine ランタイム: [Bob-Ddong-Iri-Hoyo/wine-build](https://github.com/Bob-Ddong-Iri-Hoyo/wine-build)
- DXMT ランタイム: [Bob-Ddong-Iri-Hoyo/dxmt-er-build](https://github.com/Bob-Ddong-Iri-Hoyo/dxmt-er-build)
- ランチャーアプリ: [Bob-Ddong-Iri-Hoyo/BDIH-Launcher](https://github.com/Bob-Ddong-Iri-Hoyo/BDIH-Launcher)

<Aside type="caution">
このセクションのコマンドは、それぞれのソースリポジトリのルートで実行する前提です。
この文書サイトのリポジトリ内でそのまま実行するコマンドではありません。
</Aside>

## ビルド原則

ソース変更は追跡可能な patch set とスクリプトに残す必要があります。
`artifacts/` 配下の一時成果物、実験ログ、ローカル artifact はリリース基準ではありません。

DXMT は、既定では Wine パッケージに含めず、外部ランタイムとして管理します。
これにより、Wine を再ビルドしなくても DXMT だけを差し替えたりロールバックしたりできます。

リリースビルドには、一時的な診断カウンター、トレースコード、ローカル実験パッチを残さない方針です。
測定用の debug build と、ユーザーに配布する release build は分けて扱います。

## 現在の基準

| 構成要素 | 基準 |
| --- | --- |
| ランチャーアプリ | Electron 41、React 19、TypeScript 6、Webpack 5 |
| 現在の WineHQ 系列 | `wine-winehq-11.11` |
| WineHQ 比較/互換系列 | `wine-winehq-11` |
| CrossOver 系列 | `wine-crossover-26.1.0` |
| DXMT | `v0.80` |
| Eternal Return 向け DXMT パッチ | `sanitizeOutput` のみ |

WineHQ 11.11 は現在の WineHQ 系列の基準ビルドです。
WineHQ 11.0 は比較と互換性のための fallback ラインとして維持しています。
CrossOver 26.1.0 は Eternal Return の検証を中心に扱う別系列です。

## ビルドが失敗したとき

まず次の項目を確認します。

- コマンドを対象リポジトリのルートで実行しているか確認します。
- Wine バージョン、DXMT tag、patch set、toolchain バージョンが文書の基準と一致しているか確認します。
- `clean.sh` の後に同じ patch set をきれいに再適用できるか確認します。
- 古い prefix や残った DLL が新しいランタイムと混ざっていないか確認します。

互換レイヤーのプロジェクトは、依存関係のバージョンとローカル prefix の状態に強く影響されます。
小さなバージョン差や古い prefix-local DLL でも、ビルド成功後のランタイム問題につながることがあります。
